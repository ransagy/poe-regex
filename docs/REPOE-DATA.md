# RePoE data sources

This repository consumes a deliberately small, manifest-backed slice of the
public RePoE exports. The inventory below is enforced by
`dotnet run --project tools/PoeRegex.Data.Build -- data-audit --check`; the
machine-readable source of truth is
[`data/repoe.manifest.json`](../data/repoe.manifest.json).

## Exports

| Export | URL | Use |
|---|---|---|
| PoE2 game data | <https://repoe-fork.github.io/poe2> | Catalog, corpus, exact table |
| PoB data | <https://repoe-fork.github.io/pob-data/poe2> | Development cross-check only |

The PoB export is **not shipped**. `ModRunes.min.json` is useful to verify the
RePoE augment lines, but the catalog is built from RePoE only.

## PoE2 files

### Used

| File | Consumer | Purpose |
|---|---|---|
| `mods.min.json` | `CatalogBuilder` | Affix, implicit, corrupted and desecrated modifier records |
| `base_items.min.json` | `CatalogBuilder` | Base names, tags, implicits, requirements, properties |
| `item_classes.min.json` | `CatalogBuilder` | Item class ids, display names, categories |
| `mods_by_base.min.json` | `CatalogBuilder` | Authoritative base/tag to mod mapping |
| `stat_value_handlers.min.json` | `StatTextRenderer` | Stat value rendering |
| `stats_by_file.min.json` | `CatalogBuilder` | Stat text templates |
| `augments.min.json` | `AugmentCatalogBuilder` | Rune/Soul Core/Idol/Abyssal Eye effects by target |
| `stat_translations/stat_descriptions.min.json` | `CatalogBuilder` | Stat translations |
| `stat_translations/advanced_mod_stat_descriptions.min.json` | `CatalogBuilder` | Advanced mod translations |

### Mapped but not used yet

`active_skill_types`, `ascendancies`, `audio`, `buff_visuals`, `buffs`,
`characters`, `cost_types`, `default_monster_stats`, `flavour`, `gem_tags`,
`keywords`, `skill_gems`, `skills`, `tags`, `tag_details`, `uniques`,
`world_areas`, plus the other `stat_translations/*` domains.

### Not relevant to this pipeline

`Art/`, `Metadata/`, and `passive_skill_trees/`; `base_items/` is the
per-base tree whose aggregate is already used.

`augments.min.json` is generated by RePoE's
`RePoE/parser/poe2/augments.py` from `SoulCores.dat64`,
`SoulCoreStats.dat64`, and stat descriptions. It is the authoritative source
for a rune's target category and rendered effect lines.

The catalog applies the same unique-only policy as base implicits and
corrupted enchantments: an augment family is kept only on classes where at
least one of its effect patterns is not already represented by a normal,
desecrated, implicit or corrupted family. All tiers of a kept family are kept
together. The filter is family-aware, not tier-row-by-tier-row, and also
deduplicates effects across augment families and types.

This pass covers the 63 basic tiered runes, 52 Soul Cores, and 4 Abyssal Eyes.
Target mapping covers every exported target string, including `All Equipment`,
`Weapon`, shields/bucklers/foci, specific slots, and compound targets such as
`One Hand Mace or Quarterstaff`. After target mapping and duplicate removal,
234 target rows across 118 families remain; the vendor/safety corpus still
carries every raw augment line.

Bonded effects are a separate `bonded` source with a Bonded tag. They are
Shaman-only in game, but the copied item text can contain `Bonded: … (rune)`,
so the picker can search them. The All-gear union merges the same effect
across target categories and lists the targets; per-slot views keep the single
target. It applies the same dedup rule across classes. Special/transformative runes, idols, jewels, Congealed Mist,
and the socket model remain parked for later passes.

## PoB files

`ModRunes.min.json`, `ModItem.min.json`, `ModJewel.min.json`,
`ModFlask.min.json`, `ModCharm.min.json`, `ModCorrupted.min.json`,
`ModIncursionLimb.min.json`, `ModItemExclusive.min.json`, `ModMap.min.json`,
`ModScalability.min.json`, `ModVeiled.min.json`, `QueryMods.min.json`,
`Bases/`, `Skills/`, `StatDescriptions/`, `Uniques/`, and
`TimelessJewelData/` are mapped in the manifest. Only `ModRunes` is used as a
development cross-check; no PoB file is committed or embedded.

## Sync procedure

```sh
# 1. Notice new/removed export files before fetching.
dotnet run --project tools/PoeRegex.Data.Build -- data-audit --check \
  --out /tmp/opencode/repoe-audit.md

# 2. Refresh all "used" files as one snapshot.
dotnet run --project tools/PoeRegex.Data.Build -- fetch --refresh

# 3. Rebuild the shipped artifacts.
dotnet run --project tools/PoeRegex.Data.Build -- build
dotnet run --project tools/PoeRegex.Data.Build -- corpus
dotnet run --project tools/PoeRegex.Data.Build -- matrix-solve --from-scratch \
  --prefer /tmp/opencode/poe2.fragments.previous.json \
  --jobs 2 --timeout 60
```

`fetch` writes `data/repoe.snapshot.json` with the download date, byte sizes
and SHA-256 hashes. The snapshot is metadata; raw exports stay under
`data/raw/` and are gitignored.

The audit is available as a manual/weekly **data-audit** workflow. It is a
release-prep gate, not a PR-blocking network check.

The exact solver has a fail-closed per-pattern timeout and searches in
increasing length bands (48/96/160/250). A timeout fails the build with the
scope and pattern; it never falls back to an unresolved or current-only entry.
